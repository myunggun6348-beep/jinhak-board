# 3학년 진학 현황판

고등학교 3학년 담임들이 반별 대입 지원 현황을 함께 입력하고, 사고로 이어지는 일곱 가지 상황을 자동으로 점검하는 웹앱.

- 게시 주소: https://claude.ai/artifact/Moh4QXdD7Vt4Yyihz26kta
- 소스: `index.html` 한 파일 (외부 CSS·JS 없음)

## 이 앱이 막으려는 것

표를 만드는 게 목적이 아니다. 12월에 실제로 사고가 나는 지점이 정해져 있고, 그걸 자동으로 잡는 것이 이 앱의 존재 이유다.

| | 규칙 | 왜 |
|---|---|---|
| ① | 6장 초과 | 수시 지원은 6장 제한. 산업대·전문대·과기원·사관학교는 제한 외 |
| ② | 면접·고사일 중복 | 원서 쓸 때는 안 보이다 11월에 드러남 |
| ③ | 수시 합격자의 정시 지원 | 등록을 포기해도 그해 정시·추가모집 지원 불가 |
| ④ | 이중등록 | 입학 취소 사유 |
| ⑤ | 충원 마감 임박 | 마감 시각이 대학마다 다르고, 전화 미응답은 그대로 탈락 |
| ⑥ | 수능최저 미충족 | 교과·논술 전형 탈락의 최대 변수. 사실상 탈락이므로 정시로 돌려야 함 |
| ⑦ | 결과 미입력 | 발표일이 지났는데 상태가 지원완료·1단계합·면접완료 그대로. 발표가 나도 아무도 입력하지 않으면 뒤의 경고(정시 지원 불가, 이중등록)가 전부 눈을 감는다 |
| ⑧ | 군중복 | 4년제 정시를 같은 군(가·나·다)에 두 곳 이상. 군이 비어 있으면 "군 미입력"으로 알린다. 전문대 정시는 군 제한이 없어 세지 않는다 |

## 구조

```
index.html          앱 전체 (HTML + CSS + JS, 한 파일)
test/run.js         회귀 테스트
test/fixtures/      실제와 비슷한 시험용 파일 (CSV·엑셀·한글)
```

한 파일로 둔 이유: 아티팩트로 게시할 때 외부 파일을 불러오지 못하므로, 나누면 게시 단계에서 다시 합쳐야 한다.

### 데이터

아티팩트의 `db` 기능(공유 문서 저장소)에 저장한다. `students/<학번>` 문서 하나가 학생 한 명이고, 그 학생의 지원 목록은 `apps` 배열로 안에 들어 있다.

```js
{ id:"30201", cls:2, no:"30201", name:"김민수",
  csat:{ kor:"3", math:"2", eng:"1", inq1:"3", inq2:"4", his:"4", mathSel:"확통", inq1t:"과", inq2t:"사" },   // 수능 등급·선택과목
  apps:[ { id, kind:"수시|정시", univ, major, jh, type, group,
           c6:true, itv:"2026-11-28", ann:"2026-12-12", due:"2026-12-26T18:00",
           status:"지원완료", mreq:"2개합 5", mmet:"미정",
           rank:"", note:"" } ],
  updatedAt:"2026-10-13T09:36:00Z", updatedBy:"u_…" }   // 마지막으로 고친 사람: user id 만 저장, 이름은 그릴 때 profiles()로
```

담임이 고른 반 번호(`jh.cls`)와 내 담당 반(`jh.mycls`)만 브라우저 `localStorage`에 남는다. 그 밖의 모든 값은 `db`에 있다.

**담당 반 잠금**: 처음 고른 반이 내 담당 반(★)이 된다. 다른 반은 보기만 되고, "이번만 고치기"(새로고침하면 다시 잠김)나 "내 담당 반으로"를 눌러야 고칠 수 있다. 입력 칸의 잠금은 `ro()`가 지금 그리는 칸의 반(`curCls`)으로 정한다.

**백업**: 전체 현황의 "전체 백업 받기"는 모든 학생을 JSON 한 파일로(`{app:"jinhak-board", savedAt, students}`), "백업 되살리기"는 그 파일의 학생을 덮어쓴다(백업에 없는 학생은 그대로). 되돌리기 가능. **정시 현황**: 반 화면의 "정시 현황"은 학생마다 수시 결과, 가·나·다군, 전문대 정시를 한 표로 보이고 빈 군에 바로 추가한다(수시 합격자는 추가 칸이 없다). 전체 현황에는 반별 정시 표가 있다. **상담용 출력**: 학생 칸 아래 "상담용 출력"은 그 학생의 수능 등급·선택과목, 지원 요약, 다가오는 일정, 수시(최저 판정과 판정 못한 이유), 정시, 확인할 것, 상담 메모 칸을 A4 한 장으로 낸다. 학부모에게 줄 수 있으므로 담임 메모(`note`)는 넣지 않는다. **진학 실적**(전체 현황, 학년 말 보고용): 학생마다 최종 결과를 등록완료 > 합격(등록포기 제외, "등록 전") > 진행 중 > 담임이 고른 진로(`fate`: 재수·취업·군 입대·기타) > 미정 순으로 정한다. 등록 기준으로 4년제·전문대 × 국공립·사립(이름의 국립·도립·시립·공립과 `PUBLIC` 목록), 수도권·비수도권(파일의 지역 칸 `region` → 괄호 속 지명 → 미상), 수시·정시, 수시 전형유형을 세고, 반별 표와 대학별 합격·등록 표를 보인다. "실적 엑셀(CSV) 받기"는 요약·구분·반별·대학별·학생별을 한 파일에 담는다. **입시 공통 일정**: 화면 위에 2027학년도 공통 일정(`KEYDATES`: 수능, 성적 통지, 수시 발표·등록·충원 마감, 정시 접수·군별 전형·발표·등록·충원 마감, 추가모집)의 다음 3개를 D-day로 보이고, "입시 일정 전체"로 펼친다. 대교협 2027학년도 대학입학전형기본사항 정리본을 서강대 2027 정시·성균관대 2027 수시 모집요강으로 확인한 날짜다. 달력 파일에도 함께 들어간다. 다음 학년도에는 이 목록을 새로 확인해 바꿀 것. **달력**: "다가오는 일정"의 "달력에 넣기"는 오늘 이후 면접·고사(하나씩, 하루 종일), 발표(날짜별 한 건), 충원 마감(그 시각)을 .ics 로 준다. UID 가 지원·종류(발표는 날짜·반)로 정해져 다시 넣으면 덮어쓴다. 알림은 전날 9시, 충원 마감은 3시간 전. **정시용 수능 점수**: `csat`에 국어·수학·탐구1·탐구2의 표준점수(`korS` 등, 국어·수학 0~200, 탐구 0~100)와 백분위(`korP` 등, 0~100)를 둔다. 영어·한국사는 등급만. 반 화면 "수능 성적 넣기"의 "표준점수·백분위" 보기에서 표로 넣거나 엑셀 8칸을 붙여넣고(범위 밖 값은 넣지 않음), "성적 CSV 받기"로 등급·점수를 함께 받는다. 학생 카드에도 칸이 있고, 정시 현황·상담용 출력에 국·수·탐2 합(`scoreSum`, 빠진 과목이 있으면 "일부")을 보인다. 대학별 환산점수는 계산하지 않는다. **일정 안내 문자**(반 화면 "일정 안내 문자", 학생 카드 "일정 안내 복사"): 학생마다 남은 면접·고사(논술·실기는 그 이름으로), 합격자 발표, 충원 합격 마감(시각·예비 번호), 수능(최저 있는 지원이 있을 때), 수시 합격자 등록(최초합·충원합이 있을 때)을 날짜순 한 줄씩 적은 글을 만든다(`noticeText`). 결과가 난 지원의 면접·발표는 `upcoming` 규칙대로 빠진다. 학생별 복사·모두 복사, 기간 2주·30일·전체. **변경 기록**: 저장할 때 마지막으로 저장·수신한 모습(`base`)과 비교해 바뀐 것을 학생 문서의 `log`(최근 80건)에 남긴다. 항목은 `{t, by(사용자 id만), w:[바뀐 내용], src(파일 넣기 등 묶음 작업)}`. 같은 사람이 3분 안에 이어 고친 것은 한 항목으로 묶고, 메모·최저 기준 문장은 내용 대신 "바뀜"만 적는다. 되돌리기도 무엇을 되돌렸는지 남기며 기록은 지우지 않는다. 학생 카드의 "변경 기록 N건", 전체 현황의 "최근 변경"(2주)에서 본다. 백업 파일에 함께 들어간다. **한눈에 보기**(반 화면·전체 현황, 접기 상태는 `jh.glance`): 결과 진행 막대(합격·충원 대기·1단계 합격/면접 완료·불합격·결과 기다림), 학생별 수시 지원 장수(6장 미만은 주황), 전형별·지역별 막대(`univRegion`), 면접·고사·발표·충원 마감 달력(이번 달부터 마지막 일정 달까지 최대 3달, 날짜를 누르면 그날 지원 목록, 빨간 날짜는 `KEYDATES`). 학생 칩 앞의 점은 전형 색(학종·교과·논술·실기·정시), 칩 색은 결과가 난 지원에만 쓴다. 대학별·학과별 표의 지원 수에는 막대. **인쇄**: 반 화면의 "인쇄"는 A4용 문서를 새 창으로(아티팩트에서는 파일로) 열고 인쇄 창을 띄운다.

## 개발

```bash
npm install     # 테스트용 라이브러리 (jszip, xlsx, playwright)
npm test        # 회귀 테스트
```

Playwright 전용 브라우저를 내려받지 못하는 PC(학교망)에서도 돈다. 전용 브라우저가 없으면 설치된 크롬, 그다음 엣지로 띄운다(`CHROME_PATH`로 직접 지정도 된다). 1분 남짓 걸리고 끝에 `✓ 모두 통과` 또는 실패한 항목을 보인다. **index.html 을 고쳤으면 배포 전에 꼭 돌린다.**

`index.html`을 브라우저에서 바로 열어도(또는 Vercel 주소) 화면은 뜬다. `window.claude`가 없으면 공용 저장소 대신 **이 브라우저(localStorage `jh.local.students`)에만** 저장한다. 처음에는 예시 학생이 보이고, 파일을 넣거나 학생을 추가하면 예시는 사라지고 넣은 자료가 남는다. 다른 컴퓨터·다른 선생님과는 공유되지 않으므로 CSV 내려받기로 주고받는다(그 CSV를 다시 넣으면 그대로 읽는다). "이 브라우저 자료 지우기"로 비운다.

`file://`나 `localhost`로 열었을 때만 `window.__dev`에 내부 함수가 노출된다. 테스트가 이 통로를 쓴다. 게시된 페이지(https)에서는 만들어지지 않는다.

## 로그인 없이 반 파일로 주고받기

Vercel 주소(로그인 없음)에서는 자료가 각자 브라우저에만 있으므로 파일로 나눈다. 담임은 반 화면 "우리 반 파일 받기"로 `진학현황_2반_날짜.json`(그 반 학생, 공용 최저 기준표, 받은 선생님 이름)을 받아 학교 메신저·공유 폴더에 올린다. 다른 선생님은 그 파일들을 화면에 한꺼번에 끌어다 놓거나 "파일 선택"·전체 현황 "반 파일 합치기"에서 여러 개 고른다(`mergeFiles`). 학생은 학번(없으면 반·이름)으로 맞추고, 더 최근에 고친 쪽(`updatedAt`)을 남기며, 변경 기록은 합친다. 되돌리기 가능. 로그인이 없는 화면에서는 처음 파일을 받을 때 선생님 이름을 한 번 물어(`jh.myname`, 이 브라우저에만) 변경 기록(`nm`)과 마지막 수정(`updatedName`)에 남긴다.

## Vercel 판 학교별 공용 장부(Firebase + 관리자 승인 + 암호화)

한 Firebase 프로젝트를 여러 학교가 함께 쓴다. `index.html`의 `FIREBASE_CONFIG`가 `null`이면 지금처럼 이 브라우저에만 저장하고, 값을 넣으면 Vercel 주소(https, localhost 제외)에서 학교 코드 화면이 뜬다. 아티팩트에서는 쓰지 않는다(아티팩트는 자체 db).

- **관리자**: 구글로 로그인해 "새 학교 만들기" → 학교 이름 → 학교 코드(예: `K7QM-3XPA-9RTD-HW2C`, 약 79비트)가 생긴다. 전체 현황 맨 아래(위쪽 "승인 대기 N" 단추)에서 가입 요청 승인·거절, 선생님 빼기, 관리자 추가(구글 이메일, 최대 10명).
- **선생님**: 로그인 없이(익명 로그인) 학교 코드·이름·반을 넣으면 `schools/{sid}/members/{uid}`에 `ok:false`로 요청이 생기고, 관리자가 승인하면 화면이 저절로 열린다. 빠지면 바로 막힌다. 같은 브라우저에서는 다시 승인받을 필요가 없고, 브라우저를 바꾸면 다시 요청한다.
- **학교끼리**: 학교 위치 `sid`는 코드에서 만든 40자(PBKDF2 15만 회)라 코드를 모르면 찾을 수 없고, 규칙이 그 학교 관리자·승인된 선생님만 자료를 읽고 쓰게 막는다.
- **암호화**: 학생·최저 기준 문서는 코드에서 만든 AES-GCM 열쇠로 이 컴퓨터에서 암호화해 `{v, iv, c, t}`로 올리고(`sealDoc`), 문서 이름도 HMAC 으로 바꾼다. 저장소에는 이름·학번·대학이 드러나지 않는다. 학교 이름과 선생님 이름·반, 관리자 이메일은 드러난다.
- 이 브라우저에 넣어 둔 자료가 있으면 처음 들어갈 때 올릴지 묻는다(반 파일 합치기와 같은 규칙). 한 번 받은 자료는 Firestore 로컬 캐시(암호문)에 남겨 다시 열 때 바뀐 것만 읽는다.

설정(한 번, 이 앱을 배포하는 사람): (1) https://console.firebase.google.com 에서 프로젝트 만들기 (2) 웹 앱(`</>`) 추가 → `firebaseConfig`를 `FIREBASE_CONFIG`에 넣기(공개돼도 되는 식별자) (3) Authentication → 로그인 방법에서 **Google**과 **익명** 사용, 설정 → 승인된 도메인에 `jinhak-board.vercel.app` 추가 (4) Firestore Database 만들기(`asia-northeast3` 서울, 프로덕션 모드) → 규칙 탭에 `firestore.rules` 붙여 게시. 무료 요금제(Spark)는 하루 읽기 5만 번을 모든 학교가 나눠 쓴다. 학교가 많아지면 사용량을 보고 종량제(Blaze)를 고려한다.

테스트는 `test/fixtures/fbmock.js`(가짜 인증·Firestore, 서로 다른 브라우저가 같은 저장소를 봄, 규칙 핵심 흉내)로 학교 만들기·승인 대기·승인·실시간 반영·학교끼리 막힘·틀린 코드·빼기를 본다. 실제 규칙은 Firebase 콘솔의 규칙 놀이터에서 확인한다.

## 알아 둘 것

**구형 `.hwp`는 열 수 없다.** 이진 형식이라 브라우저 안에서 풀 방법이 없다. 앱은 이 파일을 거절하면서 한글에서 `.hwpx`로 저장하는 방법을 안내한다. `.hwpx`는 압축된 XML이라 표를 읽어낸다.

**외부 라이브러리는 cdnjs에서만 받는다.** 아티팩트의 보안 정책이 그 외 주소를 막는다. 지금 쓰는 것은 두 가지.

- `jszip` — `.hwpx` 압축 풀기
- `xlsx` (SheetJS) — 엑셀 읽기
- `pdf.js` — PDF에서 글자와 위치 읽기

없으면 해당 형식만 안내 문구를 띄우고 나머지는 정상 동작한다.

**PDF에는 표가 없다.** 글자 조각과 그 위치만 있다. 진학 프로그램이 뽑은 표(예: "관심대학 리스트")는 긴 칸이 두세 줄로 접혀 있어서, 같은 높이끼리 묶으면 한 지원이 여러 줄로 쪼개진다. 그래서 맨 왼쪽 일련번호 열(가운데 맞춤이라 가운데 위치로 찾는다)을 줄의 기준으로 삼아 위아래 범위를 한 줄로 보고, 머리줄 글자 위치로 열 경계를 정해 접힌 조각을 칸마다 이어 붙인다. 번호 열이나 머리줄을 못 찾으면 같은 높이끼리 묶는 예전 방식으로 읽는다. 사진을 찍어 만든 PDF는 글자가 없어 읽지 못한다. 그런 경우 표를 복사해 `Ctrl+V`로 붙여넣으면 된다(입력 칸 안은 제외).

**진학 프로그램 표의 열.** 학번이 없으면 `학년·반·번호`로 만든다(3·2·1 → 30201). `반` 열이 있으면 지금 고른 반이 아니라 그 반 학생으로 넣는다. `수능최저유무`가 N이면 최저 "없음", Y이면 "최저 있음(기준 미기재)"로 두고 기준 문장은 담임이 채운다. `세부유형`은 전형명, `논술·실기·적성일자`는 면접일이 비었을 때 면접·고사일로 쓴다. `설립구분`이 전문대·산업대 등이면 6장 제한에서 뺀다.

**같은 파일을 다시 넣어도 늘어나지 않는다.** 대학·모집단위가 같고(띄어쓰기·가운뎃점 무시) 전형명이 같거나 한쪽이 비어 있으면 같은 지원으로 보고 갱신한다. 파일에 없던 값(상태·전형유형·6장 포함)은 기본값으로 덮지 않으므로, 결과를 입력한 뒤 명단 파일을 다시 넣어도 합격 상태가 지워지지 않는다. 면접·고사일 경고는 같은 날 서로 다른 대학일 때만 띄운다.

**파일은 넣으면 바로 들어간다.** 확인 단계 대신 "학생 N명 · 지원 M건" 요약과 되돌리기 버튼을 보여준다. 표 모양은 가리지 않는다. 머리줄이 있으면 열 이름으로(괄호·공백·번호를 떼고, 안 되면 낱말이 들어 있는지로), 머리줄이 없으면(PDF 등) 대학처럼 생긴 칸을 찾아 그 줄을 읽는다. 대학 열이 여럿이면(대학1·대학2, 수시1~6) 한 줄에서 지원 여러 건을 꺼내고, 이름 칸이 비어 있으면(병합된 칸) 바로 위 학생으로 본다. 표 모양별 회귀 테스트는 `test/run.js`의 "여러 가지 표 모양".

**추측은 하되 숨기지 않는다.** 상태 낱말이나 날짜 형식은 학교마다 다르므로 흔히 쓰는 표현을 폭넓게 받아들이되, 알아보지 못한 값은 지어내지 않고, 넣은 뒤 나오는 안내에 원문과 함께 적는다. 충원 마감에 시각이 없으면 임의로 채우지 않는다. 마감 시각을 잘못 채우면 전화를 놓친다.

**낱말 판별은 순서가 중요하다.** `불합격`은 `합격`을 품고, `1단계 불합격`은 `불합격`을 품고, `미충족`은 `충족`을 품는다. 부정 표현을 먼저, 좁은 뜻을 먼저 본다. 이 순서가 틀려 불합격이 합격으로 뒤집히는 버그가 한 번 있었다. `test/run.js`의 상태 낱말 표가 그 회귀 테스트다. **`STATUSMAP`이나 `MINMAP`을 건드렸으면 반드시 `npm test`를 돌릴 것.**

**수능최저는 자동 판정하되, 확실할 때만 한다.** 학생 카드나 반 화면의 "수능 등급 넣기"(반 전체를 표 한 장에, 엑셀에서 붙여넣기 가능)에 등급을 넣으면 각 지원의 `수능최저 기준` 문장(예: `국수영탐 중 2개합 5, 한국사 4`, `수학 포함 3합 7`)을 읽어 `최저 충족`을 채운다. 요강 문장 그대로도 읽는다: `사/과탐(1과목)`, `상위 2개 영역 등급 합이 5 이내`, `한국사 응시`, `탐구 2과목 응시, 상위 1과목 반영`, `영어 1·2등급은 1등급으로 간주`, `국어, 수학 중 1개 포함`, `상위 1개와 수학 합`. 다음 경우엔 판정하지 않고 이유만 보인다.
- 알아보지 못한 표현이 남음
- 선택과목 조건 중 앱이 모르는 것("미적/기하 지정", "또는" 등). 수학 선택(`csat.mathSel`: 확통·미적·기하)과 탐구 과목(`inq1t`·`inq2t`: 사·과)을 넣으면 확통 1등급 하향, 과탐 1과목 이상 필수, 과탐 응시자 우대(성균관대)는 판정한다. 선택과목을 몰라도 결과가 어느 쪽이든 같으면 판정하고, 갈릴 때만 넣어 달라고 한다. 제2외국어·한문 대체는 좋아질 수만 있으므로 대체 없이 충족이면 충족, 아니면 직접 확인
- 탐구 반영 방식(1과목·2과목 평균·절사)이 적혀 있지 않아 결과가 갈림
- 필요한 등급이 비어 있음

판정은 등급이나 기준을 고칠 때만 다시 한다. 그 사이 담임이 직접 고른 값은 그대로 둔다. 판정 규칙을 건드렸으면 `test/run.js`의 수능최저 표를 같이 고칠 것.

**되돌리기는 그 동작이 바꾼 학생만 되돌린다.** 동작 직전·직후를 비교해 바뀐 학생만 기억하므로, 그사이 다른 선생님이 고친 다른 학생은 건드리지 않는다. 기록은 열린 창에만 있고 새로고침하면 사라진다.

**학번 없이 들어온 학생은 이름으로 맞춘다.** 지원 현황 파일에 학번이 없으면 학번 없이 저장된다. 나중에 학번이 든 명단을 넣으면 같은 반·같은 이름의 학번 없는 학생을 찾아 학번만 채운다(새 학생을 만들지 않는다). 같은 반에 동명이인이 있으면 첫 사람에게 붙으니 확인할 것.

**수능최저 기준표(db `minreq`)는 학교 공용이다.** 진학 프로그램 파일에는 최저 "있음/없음"만 있는 경우가 많다. 그래서 2027학년도 요강에서 찾은 기준 문장을 대학·모집단위·전형명별로 출처와 함께 이 표에 넣어 두고, 같은 지원의 최저 칸이 비었거나 "최저 있음(기준 미기재)"이면 표로 채운다(파일을 넣을 때와 앱을 열 때). 담임이 최저를 직접 고쳐 적으면 그 문장도 "담임 입력"으로 표에 올라간다. 앱은 바깥 사이트에 접속할 수 없으므로 요강을 찾아 표에 넣는 일은 앱 밖에서 한다(Claude 에게 맡긴다). 문서 이름은 `minId(minKey(지원))` 이다. 표에 없는 지원은 넣을 때 "기준 문장이 없는 지원 n건"으로 알린다.

## 개인정보

학생 이름·학번·합불이 담긴다. 게시된 페이지는 기본이 비공개이고, 공유 메뉴에서 초대한 사람만 열 수 있다. 3학년 담임으로 한정해 공유할 것. `수정 가능` 권한이라야 입력할 수 있고, 보기 권한만 있으면 입력 칸이 잠긴다.
